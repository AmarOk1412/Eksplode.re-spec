## Server and Terminal Options

Extend existing manual parsers/help and docs together; keep existing bind, HTTP/game port, origin, mode, size, time and friendly-fire options.

| Option | Contract |
| --- | --- |
| `--server-id ID` | Stable host ID, 1-64 ASCII identifier characters; autogenerated process-local default |
| `--max-rooms N` | 1-128, default 32; clear ServerFull response at limit |
| `--known-server ID,GAME_ADDR,WEB_ORIGIN` | Repeatable, max 16; commas in components forbidden; GAME_ADDR is host:port or bracketed IPv6:port; origin is http(s) scheme/host/port only, no userinfo/path/query/fragment |
| `--max-connections N` | Existing web option coherently bounds integrated host; default 256, range 4-1024 |
| Existing `--bots N` | Default bots applied after each explicit room creation, at most capacity minus one; never creates an invisible startup room |

`eksplode-re-cli join ADDR --name NAME` now opens the directory after handshake rather than implicitly taking the only room. Add optional `--room-id ID` for explicit selection, still validated by host. CLI host mode creates its initial room explicitly after setup and can expose the same multi-room service; local nonnetwork play stays unchanged. Passwords are masked interactive entry, never argv flags. CLI offers a clear reconnect action while proof remains in process memory; exiting the process discards it.

Invalid configuration fails before listeners start with exit code 2 and a safe message; missing values/duplicate IDs/malformed addresses never panic. No log-output flag is necessary: significant events go to stdout by default. Human banners/help, diagnostics and warnings use stderr when running a server so stdout remains machine-readable. Terminal-host screen rendering must use stderr/terminal output independent of stdout JSONL; when stdout is a terminal, preserve TUI rendering without interleaving log text into its display region.

## Stdout Event Schema

One JSON object per line, schema version 1:

```json
{"schema":1,"timestamp_ms":1793145600000,"sequence":42,"level":"info","event":"room.created","server_id":"alpha","server_epoch":"0123456789abcdef0123456789abcdef","room_id":"1123456789abcdef0123456789abcdef","actor_id":"2123456789abcdef0123456789abcdef","room_revision":1,"tick":null,"outcome":"accepted","details":{"mode":"normal","capacity":4,"password_required":true}}
```

Fields `room_id`, `actor_id`, `room_revision` and `tick` may be null when inapplicable. `timestamp_ms` is UTC Unix epoch milliseconds from the service clock, not simulation input. Sequence increases for every attempted event; gaps plus a later drop-summary expose queue overflow. Room references remain valid only within server epoch. Serialize typed fields, not arbitrary strings from incoming frames. Emit records after accepted state mutation or the decision to reject; never log a commit before it succeeds.

Required categories:

- `server.started`, `server.stopping`, `server.stopped`.
- `room.created`, `room.settings_changed`, `room.owner_changed`, `room.closed`.
- `player.joined`, `player.join_rejected`, `player.left`, `player.disconnected`, `player.resumed`, `player.resume_rejected`, `player.reservation_expired`, `player.removed`.
- `permission.denied`, `request.rate_limited`, `protocol.rejected`.
- `match.started`, `match.ended`; significant core events use `game.<event_name>`, including bomb placement/explosion, power collection, heart loss, elimination and end-pattern transitions when available. Map every existing core Event variant explicitly in implementation; exclude routine movement and repeated animation/tick updates. A change to this mapping requires tests.
- `discovery.source_available`, `discovery.source_unavailable`, `discovery.source_incompatible`; report health transitions, not every successful polling tick. Rate-limit repeated failure summaries to once per source/minute.
- `logging.records_dropped` with exact accumulated count; unhealthy writer reports once to stderr.

Settings details use explicit safe fields and changed-field names, not a serialized request. Never output password values, password verifiers/salts, reconnect proofs, raw frames, full observations, authorization headers or full URLs containing userinfo/query/fragment. Actor ID suffices; player names are not required. Automated tests use known canary secrets and assert absence from every sink and error path, including malformed payload errors.

One writer drains a bounded 4,096-record queue. Under normal operation every significant event is recorded; ordinary three-room acceptance scenarios require zero drops. During queue saturation or output failure, logging MUST NOT block gameplay. Count every record that cannot be delivered, including failed writes and records discarded while the sink is unhealthy, and retain an exact accumulated loss count. Overflow/loss is reported as logging.records_dropped when output recovers; a failed write with uncertain delivery is conservatively counted as lost. No finite nonblocking sink can guarantee lossless records under a permanently blocked stdout consumer; this limitation must be documented. Shutdown drains for at most two seconds, then reports remaining records to stderr and terminates without waiting indefinitely for a blocked writer.

## Screen and Input Contract

Extend existing `app.js`, `room.js`, `nav.js` and terminal setup/lobby screens. Owner controls derive from server owner identity and phase, not first-human-slot inference.

| Context | Actions and required state |
| --- | --- |
| Directory | Refresh, source status, local/known filter, distinguishable room selection, Create, Join, reconnect offer when proof exists |
| Create/settings | Existing room controls plus capacity and protected-room password; owner-only editing; errors inline and focus on invalid field |
| Password entry | Masked field, confirm/cancel, bounded input, no accidental gameplay or secret persistence in room defaults |
| Lobby | Explicit owner/absent/reserved state, members/bots/capacity, owner removal and bot/settings/start controls, own ready/look/leave |
| Reconnect | Window remaining, same-operation retry, store replacement proof before acknowledgment, expired/revoked/closed reason and return to directory; no automatic fresh join under another identity |
| Cross-server handoff | Host identity, explicit leave confirmation when needed, destination progress/error/retry; no credential transfer |
| Match/results | Existing gameplay, menus, final standings and explicit Return to Lobby remain unchanged |

- Keyboard: visible focus, Tab/Shift+Tab order, native select/input keys, Enter/Space activation, Escape closes the top layer and restores opener focus; Escape never leaves a room or match.
- Controller: existing selected-device D-pad/stick focus, A activation/text-entry keyboard, B back, Start menu; held buttons ignored until released on context transition. Password on-screen keyboard uses masked target display; no secret in accessibility labels or telemetry.
- Text fields/dialogs suppress gameplay input and clear held actions when opened/closed. Keyboard bindings and controller selection remain configurable from feature 005.
- Mobile: directory/forms usable at 360x640 portrait and 844x390 landscape, native password keyboard and scrollable forms; retain bottom-left movement and bottom-right actions in portrait, existing landscape layout, conditional Punch and orientation/cancel/blur input clearing. Support Firefox for Android without browser-name branching.
- Terminal: keyboard-only directory/setup, masked password, explicit owner controls, reconnect and remote selection; preserve custom gameplay keys and small-terminal warnings. Existing browser-only controller/touch behavior does not imply adding terminal gamepad support.
- Room closure/removal clears local credentials and held input, dismisses stale room layers and puts focus on a useful directory control. Closing results does not leave the room. Lists updating under focus preserve selected room identity or move to the nearest enabled item.
- Admission timeout shows outcome unknown, retaining the original request ID for RequestStatus/CancelRequest reconciliation; never offer a fresh admission as if the first certainly failed. Keep the pending resume request ID with origin-scoped recovery state until acknowledgment; neither request-status private replies nor old/new proofs enter URLs, logs or default room storage.

See the retained [navigation](../../006-mouse-free-game-navigation/contracts/navigation-controls.md) and [touch](../../007-mobile-gameplay/contracts/touch-controls.md) contracts for unchanged behavior.

## Deployment and Documentation

Known-server destinations are operator-controlled; validate identity and never follow remote-advertised replacement origins or recursive registries. Preserve existing WebSocket Origin validation. Public browser hosting requires HTTPS/WSS termination, and plaintext TCP requires a trusted network or authenticated encrypted tunnel. Do not describe room passwords as network encryption or persistent user authentication.
